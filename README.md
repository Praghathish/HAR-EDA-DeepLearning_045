# Human Activity Recognition Using Smartphone Sensor Data

## Overview
This project performs exploratory data analysis, statistical visualization, preprocessing, and deep learning classification on the UCI Human Activity Recognition Using Smartphones dataset.

## Research objective
Classify six activities—walking, walking upstairs, walking downstairs, sitting, standing, and laying—from 561 engineered smartphone sensor features.

## Dataset
- Source: UCI Machine Learning Repository
- Dataset page: https://archive.ics.uci.edu/dataset/240/humanactivityrecognitionusingsmartphones
- The notebook downloads the dataset automatically from the UCI archive.
- Do not commit the full extracted dataset unless your instructor requires it and the repository size is acceptable. Include the dataset source link instead.

## Contents
- `HAR_EDA_DeepLearning.ipynb` — full EDA, preprocessing, MLP training, evaluation, visualizations, and exports.
- `Project_Report_Template.docx` — editable report template. Replace bracketed fields and insert actual results/figures after running the notebook.
- `requirements.txt` — Python dependencies.
- `figures/` — destination for generated plots; figures are created by the notebook.
- `results_summary.json` — generated after a successful run; not included before running because no experimental results have been fabricated.

## Method summary
- Stratified train/validation split from the official training partition.
- Official test partition retained for final evaluation.
- Median imputation and standardization fitted only on the training split.
- At least six EDA plots, including class distribution, histograms, boxplots, correlation heatmap, scatter plot, and skewness.
- MLP deep learning classifier with basic validation-based hyperparameter selection and early stopping.
- Evaluation includes loss/accuracy curves, confusion matrix, one-vs-rest ROC curves, macro ROC-AUC, and permutation importance.

## Reproducibility and limitations
Random seeds are set where practical. TensorFlow operations and platform differences can still cause small numerical differences. The dataset uses engineered features; future work could model raw sensor time windows using a 1D CNN or LSTM. Permutation importance is computed on a small sample and a subset of features, so interpret it as exploratory rather than causal.
